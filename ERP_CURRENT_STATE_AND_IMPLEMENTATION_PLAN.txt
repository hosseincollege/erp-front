# ERP Pro: Current State & Implementation Roadmap (v2.0)

## 1. Project Overview & Architecture
An organization-centric ERP system built for multi-tenancy.
- **Backend:** NestJS, Prisma (PostgreSQL), JWT Auth.
- **Frontend:** Next.js 14+ (App Router), Tailwind CSS, Lucide Icons.
- **Core Pattern:** Every entity is scoped by `organizationId`. Multi-tenant logic is enforced at the database and service level.
- **Frontend Pattern:** `ModulePage` layout for consistency, standalone API clients (e.g., `accounting-api.ts`), and theme-aware UI (Dark/Light mode using CSS tokens).

## 3. Module Development Sequence (The "Blueprint")

For each upcoming module (CRM, HR, Inventory, Purchases), the AI assistant must provide files in this specific order:

### Phase A: Frontend Foundation
1. `src/types/[module].ts`: Full TypeScript interfaces (Models + DTOs).
2. `src/lib/[module]-api.ts`: API client based on the `api-client.ts` pattern.
3. `src/app/(workspace)/[module]/page.tsx`: Main list/dashboard with standard filters and search.

### Phase B: Frontend Forms & Details
1. `src/app/(workspace)/[module]/new/page.tsx`: Creation/Edit forms using standard UI components.
2. `src/app/(workspace)/[module]/[id]/page.tsx`: Detailed view with status-based action buttons.

### Phase C: Backend Infrastructure
1. `backend/prisma/schema/[module].prisma`: Database models with mandatory `organizationId`.
2. `backend/src/[module]/dto/`: DTOs for Create/Update with `class-validator`.
3. `backend/src/[module]/[module].service.ts`: Business logic with organization scoping.
4. `backend/src/[module]/[module].controller.ts`: REST endpoints.
5. `backend/src/[module]/[module].module.ts`: NestJS module registration.

## 4. Coding Rules & Constraints
1. **No Mock Data:** Service methods must use Prisma; API clients must call real endpoints.
2. **Organization Scoping:** Every `findMany`, `findUnique`, `create`, and `update` must include `organizationId` from the request user.
3. **UI Theme:** Use project CSS variables (`--background`, `--foreground`, etc.) instead of hardcoded white/black classes to support Dark Mode.
4. **Standard Responses:** Use the `ApiResponse<T>` wrapper for all backend returns.
5. **Localization:** All labels and messages in the UI must be in Persian (Farsi), but code (variables, routes) must be in English.
